/workflow create "Gutenberg Plugin with Full QA Pipeline"

Context: We are building a production-ready WordPress plugin that features a custom Gutenberg block UI. The codebase must adhere to strict WordPress Coding Standards (WPCS) and include a comprehensive testing suite.

Please spin up the following parallel sub-agents to handle this project:

1. @LeadDevAgent - The Architect & UI Builder
- Scaffold the core WordPress plugin structure (OOP PHP architecture).
- Build the user interface exclusively using Gutenberg blocks (React, `@wordpress/block-editor`, `@wordpress/components`).
- Set up `package.json` with `@wordpress/scripts` for the build process.
- Ensure the React UI state communicates securely with the WordPress REST API or admin-ajax using nonces.

2. @TestEngineerAgent - The Testing Setup
- Configure PHPUnit for backend unit testing.
- Set up `wp-env` for a containerized local testing environment.
- Scaffold End-to-End (E2E) tests using the `@wordpress/e2e-test-utils-playwright` package.
- Write initial boilerplate tests: one PHPUnit test checking plugin initialization, and one E2E test verifying the Gutenberg block loads in the editor without console errors.

3. @QASubAgent - Code Standards & Final Review
- Configure PHP_CodeSniffer (PHPCS) enforcing the `WordPress-Extra` and `WordPress-Docs` rulesets.
- Set up a GitHub Actions workflow file (`.github/workflows/qa.yml`) that automatically runs the build step, PHPCS, PHPUnit, and Playwright tests on every PR.
- Review the code generated by @LeadDevAgent for common WordPress security vulnerabilities (e.g., missing escaping `esc_html()`, missing sanitization, CSRF vulnerabilities).

Execution Rules:
- @LeadDevAgent must complete the scaffolding before @TestEngineerAgent injects the testing files.
- @QASubAgent has final approval and should output a terminal report of any PHPCS warnings or E2E failures that the other agents need to fix before completing the workflow.
- Output the final source code into a clean directory structure.
